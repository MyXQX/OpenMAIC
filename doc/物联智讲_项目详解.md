## 一句话定位

**物联智讲 = 在 OpenMAIC 项目里挂载一个独立子模块（路径 `/wulian`），用「科学家 persona + 多 Agent + 轻量 RAG + 物理模拟器」实现『让法拉第本人讲电磁感应』式的大学物理课堂。**

它**不替换**也**不依赖** OpenMAIC 的核心课堂内核（`lib/orchestration`、`lib/playback`、`components/slide-renderer` 等都没有被引用），而是作为同一个 Next.js 项目的并行入口。原有的 `/`、`/classroom/[id]` 等路由完全不受影响。

入口路径：

- `/wulian`：章节选择首页
- `/wulian/lesson/<chapterId>`：课堂页（旗舰章节为 `em-induction`）
- `/api/wulian/*`：所有后端接口

## 已交付内容清单

### 4 个章节（content/wulian/chapters/*.json）

| 章节 ID           | 学科     | 主讲科学家           | 状态     | RAG 语料量                         |
| ----------------- | -------- | -------------------- | -------- | ---------------------------------- |
| `em-induction`  | 电磁学   | 法拉第（+ 麦克斯韦） | ✅ ready | 4 个 markdown，约 14 chunk（旗舰） |
| `newton-laws`   | 力学     | 牛顿                 | preview  | 1 个 markdown                      |
| `double-slit`   | 光学     | 惠更斯（+ 麦克斯韦） | preview  | 1 个 markdown                      |
| `photoelectric` | 近代物理 | 爱因斯坦（+ 玻尔）   | preview  | 1 个 markdown                      |

「ready」的章节具备完整内置语料；preview 章节也能完整跑通对话/白板/小测/上传，只是教材片段精简。

### 6 位科学家 Persona（content/wulian/scientists/*.json）

法拉第 Faraday、麦克斯韦 Maxwell、牛顿 Newton、爱因斯坦 Einstein、玻尔 Bohr、惠更斯 Huygens。每位有：身份、年代、代表公式、说话风格、LLM `systemPromptPersona` 片段、`visualKey`（决定头像渐变色）。

### 3 类 Agent

- **科学家导师（teacher）**：主讲，按章节绑定到对应科学家。
- **小麦 助教（assistant）**：基于 RAG 答疑，结构化回答，类似研究生学长口吻。
- **小恒 同学（classmate）**：主动提**典型误区**让老师有机会纠正，第一人称、稍带犹豫的本科生口吻。

### 4 个内置物理模拟器（app/wulian/components/Simulation.tsx）

| simulationId         | 物理意义                           | 控制变量                    |
| -------------------- | ---------------------------------- | --------------------------- |
| `flux-loop-slider` | 磁通量 → 感应电动势（含旋转动画） | B（磁场）、面积、夹角       |
| `photoelectric`    | 光电效应（频率/强度 → 动能）      | 频率 ν、光强、固定逸出功 W |
| `double-slit`      | 双缝干涉条纹间距                   | 波长 λ、缝距 d、屏距 L     |
| `newton-block`     | 斜面滑块（牛顿第二定律）           | 倾角、摩擦系数 μ           |

模拟器既能在白板里被「LLM 板书」嵌入（`whiteboard:[{type:'simulation',...}]`），也能作为 `fallbackSimulationId` 在白板空闲时垫场。

### 5 个 API 接口

```
GET  /api/wulian/lesson                 // 列出章节 / 章节详情 + 主讲 + 三类 agent
POST /api/wulian/chat                   // SSE 多 Agent 课堂主接口
POST /api/wulian/ingest                 // 上传 PDF/TXT/MD，解析→切块→嵌入→存储
POST /api/wulian/feedback               // 收集 quiz / rating / comment（按日 jsonl）
```

### 3 种资料模式

- **课程**：仅查内置教材（`content/wulian/knowledge/*.json`）
- **我的**：仅查上传的资料（`data/wulian/vectors/*.json`）
- **对照**：两者都查，老师会在回答中标注一致点和差异

### 内容构建脚本

`pnpm wulian:build-content` → 扫 `content/wulian/corpus/<chapter>/*.md` → 切块 → 嵌入（如配置）→ 输出到 `content/wulian/knowledge/<chapter>.json`。

**关键设计取舍**

1. **无外部基础设施**：不引入 Chroma / Pinecone / PostgreSQL / Redis / Neo4j，全部用 JSON 文件和文件系统。`pnpm dev` 即可运行。
2. **嵌入降级**：未配置 embedding 时自动走 BM25-Lite 关键词检索，演示也能跑通。
3. **持久化最小化**：服务端无状态；前端会话只在 React 组件内存里。刷新即重置。
4. **不重做 OpenMAIC 已有的内核**：不复用 LangGraph、不复用 slide-renderer / scene-renderers / playback，而是用一个 50 行的 `decideAgentSequence` 状态机自己解决。

## 技术栈

### 直接使用的技术

| 技术                            | 用途                                                              |
| ------------------------------- | ----------------------------------------------------------------- |
| **Next.js 16 App Router** | 路由 / 服务端组件 / API 路由                                      |
| **React 19**              | 客户端 UI                                                         |
| **TypeScript 5**          | 类型集中在 `lib/wulian/types.ts`                                |
| **Vercel AI SDK 6**       | `streamText`，多 LLM 提供商抽象（通过复用 OpenMAIC `lib/ai`） |
| **KaTeX 0.16**            | 公式渲染（OpenMAIC 已经全局引入了 katex.min.css）                 |
| **unpdf 1.4**             | PDF → 纯文本（OpenMAIC 已装）                                    |
| **jsonrepair 3.13**       | 修复 LLM 偶发的不合规 JSON                                        |
| **nanoid 5.1**            | docId / chunkId / messageId                                       |

### 没有使用的（刻意避开的）

- LangGraph / @langchain/langgraph：自己写一个 50 行的 sequence 状态机更轻、可读
- Tailwind 主题：避免污染 OpenMAIC 全局样式，用一份独立的 `wulian.css`，所有变量以 `--w-` 前缀定义
- Zustand：状态都在 React Hooks 里，没必要引全局 store
- 浏览器 IndexedDB / Dexie：MVP 不要求持久化前端会话
- 任何 3D 数字人 / TTS / ASR：方案 §10.3「不做清单」明确排除

## 复用 OpenMAIC 仓库哪些模块

物联智讲尽可能**只引用**，不修改 OpenMAIC 的代码。下表是物联智讲对 OpenMAIC（同仓库）的具体引用：

| 物联智讲文件                          | 引用 OpenMAIC 模块                                             | 用法                                                                                |
| ------------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `lib/wulian/agents/orchestrator.ts` | `@/lib/ai/llm` → `streamLLM`                              | 流式调 LLM。OpenMAIC 已封装好 thinking 配置注入、provider options 注入              |
| `app/api/wulian/chat/route.ts`      | `@/lib/server/resolve-model` → `resolveModelFromHeaders`  | 解析请求头里的 `x-model` / `x-api-key` / `x-base-url`，与 .env.local fallback |
| `app/api/wulian/chat/route.ts`      | `@/lib/ai/providers` → `isProviderKeyRequired`            | 校验 provider 是否需要 key（Ollama 等本地不需要）                                   |
| 所有 `app/api/wulian/*/route.ts`    | `@/lib/server/api-response` → `apiSuccess` / `apiError` | 统一错误码（`MISSING_API_KEY` / `PARSE_FAILED` / `INTERNAL_ERROR` 等）        |
| 多个文件                              | `@/lib/logger` → `createLogger`                           | 带 tag 的日志，受环境变量 `LOG_LEVEL` 控制                                        |
| `lib/wulian/rag/parse.ts`           | `unpdf`（OpenMAIC 已 `pnpm install`）                      | PDF 提取                                                                            |
| `app/wulian/components/Latex.tsx`   | `katex`（OpenMAIC 已 `pnpm install` + 引入 css）           | 公式渲染                                                                            |

**重点：物联智讲没有引用** `lib/orchestration`（LangGraph 导演图）、`lib/playback`（回放状态机）、`lib/action`（28 种动作引擎）、`lib/generation`（两阶段生成流水线）、`components/slide-renderer`、`components/scene-renderers`、`components/chat`、`components/whiteboard`（OpenMAIC 自有的 SVG 白板）。

也就是说：**OpenMAIC 提供给物联智讲的"基础设施"主要是『LLM provider 抽象层 + 服务端工具函数』**，再加上 `unpdf` / `katex` / `jsonrepair` 这些已装好的依赖。其余课堂体验（白板、模拟器、消息气泡、quiz、上传面板）都是物联智讲自己写的。

### 与 OpenMAIC 主程序的隔离

- 路由命名空间隔离：`/wulian/*` 与 `/api/wulian/*`，不会与 `/`、`/classroom/[id]`、`/api/chat`、`/api/generate/*` 冲突。
- 样式隔离：物联智讲的 `app/wulian/layout.tsx` 引入独立的 `wulian.css`，所有 CSS 变量以 `--w-` 前缀，根容器固定 `position: fixed; inset: 0`，不与 OpenMAIC 的 ThemeProvider 冲突。
- 数据隔离：`content/wulian/`、`data/wulian/` 都是新目录。

## 数据模型

所有跨模块共享类型集中在 `lib/wulian/types.ts`。下面是核心 4 个：

### Chapter（章节）

```ts
interface Chapter {
  id: string;
  title: string;
  subject: '力学' | '电磁学' | '光学' | '近代物理';
  primaryScientist: string;            // → ScientistPersona.id
  secondaryScientist?: string;
  objectives: string[];
  knowledgePoints: KnowledgePoint[];   // 含 formulas / misconceptions / simulationId
  corpusFolder: string;
  status: 'ready' | 'preview' | 'planned';
  summary: string;
  openingScript: string;
}
```

### ScientistPersona（科学家身份）

```ts
interface ScientistPersona {
  id: string;
  name: string;                // 中文名
  englishName: string;
  era: string;                 // "英国 / 1791-1867"
  field: string;
  signatureFormula?: string;   // LaTeX
  bio: string;
  systemPromptPersona: string; // 注入到 LLM 的 system prompt 中
  visualKey: 'amber' | 'indigo' | 'slate' | 'emerald' | 'rose' | 'violet';
  voiceStyle: string;
}
```

### AgentTurn（一次 Agent 发言的输出协议）

LLM 每次必须产出一个**严格符合此结构的 JSON**：

```ts
interface AgentTurn {
  speakerRole: 'teacher' | 'assistant' | 'classmate';
  speakerId: string;            // 如 "teacher_faraday" / "assistant_xiaomai"
  speakerName: string;          // 如 "迈克尔·法拉第 教授"
  speech: string;               // 80~250 字口语化讲解，不含 LaTeX
  whiteboard?: WhiteboardItem[]; // 公式 / 笔记 / SVG / 模拟器
  avatarAction?: { emotion, gesture };
  quiz?: QuizQuestion;          // 可选随堂题
  citations?: string[];         // 引用编号，如 ["#1","#2"]
  nextState?: 'continue' | 'await_student' | 'finished';
}
```

### WulianStreamEvent（SSE 事件）

```ts
type WulianStreamEvent =
  | { type: 'agent_start'; speakerRole, speakerId, speakerName }
  | { type: 'agent_delta'; speakerId; deltaText }    // speech 字段的增量
  | { type: 'agent_complete'; turn: AgentTurn }       // 完整结构（含 whiteboard、quiz）
  | { type: 'turn_end' }
  | { type: 'error'; message };
```

## 多 Agent 状态机逻辑

物联智讲的「多 Agent」是**有限状态机**而非完整的图编排。逻辑全部在 `lib/wulian/agents/orchestrator.ts` 的 `decideAgentSequence` 函数里：

```
                       runClassroomTurn(opts)
                              │
                  ┌───────────┴───────────┐
                  ▼                       ▼
        forceAgent 已指定?         forceAgent 未指定
        → 单 agent 序列            → 走默认状态机
                                       │
                       ┌───────────────┴────────────────┐
                       ▼                                ▼
            studentMessage 为空（开场）          studentMessage 非空（提问）
            → ['teacher', 'classmate']              → ['assistant']
            老师开场讲解 → 同学提一个误区          助教针对性回答
```

为什么不是无限循环？**控制延迟**：每次用户提问只跑 1~2 个 Agent（每个 ~3-8s LLM 调用），整轮 < 15s。如果让 LLM 自由轮询，体验会变差。

### 每个 Agent 的具体执行

`runOneAgent({role, opts})` 是一个 async generator：

```
yield { type: 'agent_start', speakerRole, speakerId, speakerName }
   │
   ├─ buildSystemPrompt(role, persona, chapter, retrieved, mode, ...)
   │
   ├─ buildUserPrompt(retrieved chunks 编号化 + 历史摘要 + 学生消息)
   │
   ├─ streamLLM({ model, system, prompt, temperature: role==='classmate'?0.85:0.4 })
   │
   ├─ 边接 token 边增量提取 "speech" 字段（找 "speech":"…"，注意未转义引号）
   │     └─► yield { type: 'agent_delta', speakerId, deltaText }
   │
   ├─ 全部接收完成后，用 JSON.parse + jsonrepair 兜底解析整个 JSON
   │     └─► 提取 speech / whiteboard / quiz / citations / nextState
   │
   └─► yield { type: 'agent_complete', turn }
```

**速度技巧**：先把 `"speech"` 字段流式吐给前端打字机效果，等整个 JSON 收完再补 `whiteboard` / `quiz`，让用户感觉「老师在边说边写板书」。

整轮结束：

```
for role of sequence:
  if signal.aborted: break
  yield* runOneAgent({role, opts})
yield { type: 'turn_end' }
```

### Agent 角色的 Prompt 差异（lib/wulian/agents/prompts.ts）

| 维度           | teacher（科学家）                                      | assistant（小麦）      | classmate（小恒）              |
| -------------- | ------------------------------------------------------ | ---------------------- | ------------------------------ |
| 身份注入       | `persona.systemPromptPersona`（19 世纪皇家研究院…） | 友善结构化的研究生学长 | 第一人称、稍带犹豫的本科生     |
| 教学策略       | 直观图景 → 公式 → 适用条件 / 常见误区                | 直接答疑，公式放白板   | 选最有教学价值的误区，反问老师 |
| temperature    | 0.4                                                    | 0.4                    | 0.85（更自由、更"像同学"）     |
| 推荐 nextState | 开场 `continue` / 出题后 `await_student`           | `await_student`      | `continue`（把球交还老师）   |

所有 Agent 共用同一个 `OUTPUT_PROTOCOL`（强制 JSON、严禁编造数据、引用资料用 `[#1]` 角标）。

### 公共上下文块（system prompt 的固定部分）

每个 Agent 的 system 都会注入：

1. **scenario block**：章节标题、学习目标、知识点聚焦、资料模式说明
2. **retrieval block**（user prompt）：检索到的 chunk 编号化拼接，无召回时明确告知"以下基于一般教材"
3. **conversation digest**：最近 6 条历史消息的摘要（`学生：…` / `法拉第 教授：…`）

## 前端 SSE 流式消费状态机

`useWulianChat.ts` 是一个自定义 React Hook，负责把 SSE 事件流变成 `messages[] / whiteboardItems[]` 状态。

### Hook 输出

```ts
{
  messages,           // ChatMessage[]，含用户消息和 agent 消息
  whiteboardItems,    // WhiteboardItem[]，所有 agent 累积出的板书
  activeSpeakerId,    // 当前正在说话的 speakerId（用于头像呼吸点）
  loading,
  error,
  send(userMessage, opts?),
  cancel(),
  clearWhiteboard(),
  reset(),
}
```

### 事件 → 状态转换

```
┌──────────────────┐
│ 用户输入或开场     │
│ chat.send("…")   │
└────────┬─────────┘
         │
         ▼
   ┌───────────────────────────────────┐
   │ POST /api/wulian/chat              │
   │ body = { chapterId, userMessage,  │
   │   history, uploadedDocIds, mode } │
   └────────┬──────────────────────────┘
            │
            ▼ SSE stream
   ┌─────────────────────────────────────────┐
   │ 循环读取 reader.read() → 按 \n\n 分包      │
   │ 每包 data: <json> 解析为 WulianStreamEvent│
   └────────┬────────────────────────────────┘
            │
            ▼
   ┌─────────────────────────────────────────────────────────────┐
   │ event.type:                                                    │
   │   agent_start    ─► 新建一个 agent 占位 ChatMessage（speech=''）│
   │                     activeMsgId = 它的 id                       │
   │                     activeSpeakerId = event.speakerId          │
   │                                                                 │
   │   agent_delta    ─► 找到 activeMsgId，把 deltaText 拼到 speech 末│
   │                                                                 │
   │   agent_complete ─► 用 event.turn 整体替换 activeMsgId 这条消息  │
   │                     把 turn.whiteboard 项追加到 whiteboardItems │
   │                     activeMsgId = null                          │
   │                     activeSpeakerId = null                      │
   │                                                                 │
   │   error          ─► setError(message)（不立刻终止流）            │
   │                                                                 │
   │   （流结束 / abort）─► loading = false                          │
   └─────────────────────────────────────────────────────────────┘
```

**容错**：如果没有先收到 `agent_start` 就直接收到 `agent_complete`（极少见，比如 LLM 提前完结），会把 turn 直接 push 成新 message。

**白板累积逻辑**：板书是 append-only 的，刷新前不会丢；但用户可以点「清空」手动清。多个 Agent 的板书会按时间顺序堆叠在白板里。

## RAG 检索流水线

整个 RAG 是「**轻量、可降级、零外部依赖**」的设计。

### 切块（chunk.ts）

```
markdown text
    │
    ▼ splitByHeading: 按 #/##/### 切大段（标题保留进入段落）
    ▼ windowChunks: 大段超过 700 字符按段落滑窗（重叠 80 字符）
    │
    ▼
{ id, docId, index, text: "# 标题\n…", heading, metadata, embedding: null }[]
```

### 嵌入（embed.ts）—— 嵌入降级三段式

1. **优先**：用户显式指定 `EMBEDDING_BASE_URL` + `EMBEDDING_API_KEY`（+ `EMBEDDING_MODEL`）。
2. **嗅探**：依次检查 `QWEN_API_KEY` → `OPENAI_API_KEY` → `GLM_API_KEY` → `SILICONFLOW_API_KEY`，自动用对应的 OpenAI 兼容 `/v1/embeddings`。
3. **降级**：以上都没有 → 返回 `null`，调用方自动走**关键词检索**（`keywordScore`：英文/数字按词，中文按 bigram 的 Jaccard 近似）。

这样保证：哪怕用户只配了 DeepSeek（DeepSeek 当前没 embedding 端点），demo 也能完整跑通。

### 存储（store.ts）

| 来源     | 文件路径                               | 触发                                  |
| -------- | -------------------------------------- | ------------------------------------- |
| 内置语料 | `content/wulian/knowledge/<id>.json` | `pnpm wulian:build-content`         |
| 上传文档 | `data/wulian/vectors/<docId>.json`   | `POST /api/wulian/ingest`（运行时） |

加载时**进程内 Map cache**，避免重复 IO。

### 检索（retrieve）

```
retrieve({ chapterId, query, uploadedDocIds, mode, topK=4 })
    │
    ├─ mode ∈ {course, compare} → loadChapterCorpus → searchChunks（builtin）
    │
    ├─ mode ∈ {mine, compare}   → 遍历 uploadedDocIds → loadUploadCorpus → searchChunks（uploaded）
    │
    └─ 合并 results, 按 score 排序, 截断到 topK*1.5
```

`searchChunks` 内部：

```
chunks 全有 embedding ?
   ├─ 是 → embedTexts([query]) 拿 query 向量 → cosineSim 排序 → 返回 topK
   └─ 否 → 用 keywordScore 排序 → 返回 topK
```

### 注入到 prompt

`formatRetrievalForPrompt` 把 chunks 编号化：

```
[#1] 来源：电磁感应章节(课程)
…正文…

---

[#2] 来源：我的笔记.pdf(用户)
…正文…
```

**严令 LLM 在 speech 中用 `[#1]` 角标，并把编号填入 `citations` 数组**。前端 MessageBubble 在引用区把它渲染成铜色小标签。

## API 接口详解

### 1. `GET /api/wulian/lesson`

| 参数        | 行为                                                                             |
| ----------- | -------------------------------------------------------------------------------- |
| 不带 `id` | 返回 `{ chapters: [{id,title,subject,summary,status,primaryScientist}, ...] }` |
| `?id=...` | 返回 `{ chapter, teacher, secondary, agents: [...3 类] }`                      |

> 注：当前前端没有真的调这个接口，因为课堂页用的是**服务端组件**直接读 JSON。这个接口是给 OpenClaw / 第三方集成准备的。

### 2. `POST /api/wulian/chat`（核心）

请求体：

```ts
{
  chapterId: string,
  userMessage: string,         // 空字符串 = 开场
  history?: ChatMessage[],     // 前端维护的历史
  uploadedDocIds?: string[],
  mode?: 'course' | 'mine' | 'compare',
  forceAgent?: 'teacher' | 'assistant' | 'classmate',
}
```

响应：`text/event-stream`，每包格式：

```
data: {"type":"agent_start","speakerRole":"teacher",...}\n\n
data: {"type":"agent_delta","speakerId":"teacher_faraday","deltaText":"让"}\n\n
data: {"type":"agent_delta","speakerId":"teacher_faraday","deltaText":"我们"}\n\n
...
data: {"type":"agent_complete","turn":{...完整 AgentTurn...}}\n\n
data: {"type":"agent_start","speakerRole":"classmate",...}\n\n
...
data: {"type":"turn_end"}\n\n
```

**特殊**：每 15s 发送 `:heartbeat\n\n`，防代理 30s 超时。`x-model` / `x-api-key` / `x-base-url` 头会被 `resolveModelFromHeaders` 解析，没传时回退到 `.env.local` 里的 `DEFAULT_MODEL`。

错误：`MISSING_API_KEY` (401) / `INVALID_REQUEST` (404) / `INTERNAL_ERROR` (500)。

### 3. `POST /api/wulian/ingest`

multipart form-data：`file`（PDF/TXT/MD ≤ 30 MB）+ 可选 `sessionId`。

```
file (Buffer)
  │
  ├─ parseDocument: pdf 用 unpdf, 文本直接 utf-8
  │
  ├─ 持久化原文件到 data/wulian/uploads/<docId><ext>
  │
  ├─ chunkText: 切块
  │
  ├─ embedTexts: 嵌入（失败则降级）
  │
  ├─ saveUploadCorpus: 写 data/wulian/vectors/<docId>.json
  │
  └─ 返回 { docId, filename, chunkCount, summary, hasEmbedding, ... }
```

错误：`MISSING_REQUIRED_FIELD` / `INVALID_REQUEST(413/415)` / `PARSE_FAILED`。

### 4. `POST /api/wulian/feedback`

```ts
{
  chapterId: string,
  type: 'quiz' | 'rating' | 'comment',
  payload: Record<string, unknown>,
}
```

→ append-only 写到 `data/wulian/feedback/<yyyymmdd>.jsonl`，每行一条。

## 一次完整的「学生提问」请求生命周期

以 `em-induction` 章节为例，学生输入 *"为什么楞次定律有负号？"*：

```
┌──────────────────────────────────────────────────────────────────┐
│ 1. 用户在 LessonRoom textarea 输入并按 Enter                        │
└──────────────────────────────────────────────────────────────────┘
                                ▼
┌──────────────────────────────────────────────────────────────────┐
│ 2. useWulianChat.send("为什么楞次定律有负号？")                     │
│    - 把 user message 加进 messages                                  │

└──────────────────────────────────────────────────────────────────┘
                                ▼
┌──────────────────────────────────────────────────────────────────┐
│ 3. /api/wulian/chat route                                          │
│    a. getChapter('em-induction') / getPersona('faraday')           │
│    b. resolveModelFromHeaders → 用 .env DEFAULT_MODEL（如 deepseek）│
│    c. retrieve({chapterId, query="为什么…", mode:"course"})         │
│         → 内置 14 chunks 中召回 top-4 关于楞次定律的段落             │
│    d. 创建 SSE TransformStream + 启动 heartbeat                     │
│    e. 调 runClassroomTurn({chapter, teacherPersona, …})              │
└──────────────────────────────────────────────────────────────────┘
                                ▼
┌──────────────────────────────────────────────────────────────────┐
│ 4. orchestrator.runClassroomTurn                                   │
│    a. decideAgentSequence: studentMessage 非空 → ['assistant']      │
│    b. runOneAgent({role:'assistant', …})                            │
│         - yield agent_start                                          │
│         - buildSystemPrompt（注入 SCENARIO + 助教身份 + 输出协议）    │
│         - buildUserPrompt（注入 4 个 retrieved chunks 编号化 + 历史）│
│         - streamLLM(temp=0.4)                                        │
│         - 边接 token 边解析 "speech" → 多次 yield agent_delta        │
│         - 全部完成后 JSON.parse → yield agent_complete(turn)        │
│    c. yield turn_end                                                 │
└──────────────────────────────────────────────────────────────────┘
                                ▼
┌──────────────────────────────────────────────────────────────────┐
│ 5. 前端 useWulianChat 消费 SSE                                      │
│    a. agent_start    → 新建占位 message（小麦助教，speech=''）       │
│    b. agent_delta×N  → speech 增量拼接，UI 打字机效果                │
│    c. agent_complete → 完整 turn 替换占位，whiteboard 追加到 board   │
│    d. turn_end       → loading=false                                 │
└──────────────────────────────────────────────────────────────────┘
                                ▼
┌──────────────────────────────────────────────────────────────────┐
│ 6. 用户看到：                                                       │
│    - 右侧聊天区：助教带着引用 [#1][#2] 的回答                         │
│    - 中央白板：新增的公式卡片 ε = -dΦ/dt 和说明                       │
│    - 如果 turn.quiz 不为空：底下浮出 QuizCard 让学生作答              │
└──────────────────────────────────────────────────────────────────┘
```

**开场流程**只是把第 4a 改成 `['teacher','classmate']`，依次跑两遍，UI 上会先后出现两个气泡。

## 与 OpenMAIC 的边界

为了帮你判断「修改物联智讲会不会影响 OpenMAIC」，下面列出两边的边界：

### 物联智讲完全独立、可单独删除的部分

```
app/wulian/                          整个 UI 子树
app/api/wulian/                      整个 API 子树
lib/wulian/                          整个业务模块
content/wulian/                      整个内容目录
data/wulian/                         整个运行时数据
scripts/wulian-build-content.mjs     构建脚本
.env.wulian.example                  环境模板
WULIAN-README.md                     使用文档
package.json 中的 wulian:build-content 一行
```

把这些全部删除，OpenMAIC 主程序毫发无损。

### 物联智讲对 OpenMAIC 的「单向只读」依赖

| 依赖路径                                                  | 用法 / 风险                               |
| --------------------------------------------------------- | ----------------------------------------- |
| `lib/ai/llm.ts → streamLLM`                            | 调用入口，OpenMAIC 改签名物联智讲会编译错 |
| `lib/ai/providers.ts → isProviderKeyRequired`          | 同上                                      |
| `lib/server/resolve-model.ts`                           | 依赖 header `x-model` 等约定            |
| `lib/server/api-response.ts`                            | 错误码常量集合                            |
| `lib/logger.ts → createLogger`                         | 兼容 `LOG_LEVEL` 环境变量               |
| 共用依赖（`unpdf`/`katex`/`jsonrepair`/`nanoid`） | OpenMAIC 升级时需要回归测试               |

### OpenMAIC 对物联智讲的依赖

**零**。OpenMAIC 主程序里没有任何文件 import 物联智讲的代码。

## 速读结论

读完本文档你应该能回答这些问题：

1. **物联智讲是什么？** 在 OpenMAIC 仓库里挂一个独立子模块，走 `/wulian` 路径，做大学物理多 Agent 互动课堂。
2. **它如何复用 OpenMAIC？** 只引用 `lib/ai/llm` + `lib/server/resolve-model` + `lib/server/api-response` + `lib/logger` + 已装的 `unpdf` / `katex` / `jsonrepair` / `nanoid`。OpenMAIC 自己的课堂内核（LangGraph 编排、slide-renderer、playback、action 引擎）一概没用。
3. **前端长什么样？** 首页 → 课堂页（3 列：sidebar / 白板 / chat），右栏 3 个 tab（课堂 / 我的资料 / 知识点），一个独立的实验室深蓝主题 CSS。
4. **多 Agent 怎么协作？** 50 行的 sequence 状态机：开场 = teacher + classmate，提问 = assistant；每个 agent 流式吐 `speech`，最后产出严格 JSON 包含 `whiteboard`、`quiz`、`citations`、`nextState`。
5. **RAG 怎么做？** 切块按 # 标题 + 段落滑窗 → 嵌入或 BM25-Lite 兜底 → JSON 文件持久化 → topK 余弦或关键词排序 → 编号化注入 prompt。
6. **数据存哪？** 静态语料在 `content/wulian/`，运行时数据（上传/反馈）在 `data/wulian/`。无数据库依赖。
7. **要怎么删掉它？** 删 `app/wulian/` + `app/api/wulian/` + `lib/wulian/` + `content/wulian/` + `data/wulian/` + 几个根级文件即可。
